# Slyp — Integration Verification Report

**Verified:** 2026-08-20, against `main` @ `d538c36` (HEAD, matches `origin/main`, no uncommitted source changes, no unpushed commits).
**Method:** Static analysis + direct execution of Python modules, pytest, and hand-written adversarial fixtures in `verify/`. No existing source file was modified. No real payslip was used (all fixtures are synthetic, inline in `verify/*.py`).
**Environment limits that shaped this report:** No Node.js/npm is installed in this execution environment, and no browser-automation tool is available, so the frontend could not be started, built, or driven through a real browser. This blocks a subset of Phase 2 and Phase 7 checks (marked UNVERIFIED below); everything else was independently executed.

---

## Headline finding, before the table

**The two teammates' claim — "the API and frontend work and are connected" — is false as stated, in the most direct way possible: there is no API.**

There is no HTTP server anywhere in this repository. No FastAPI, no Flask, no route handler, no `app.py`, no port binding — grepped for all of them, zero matches. The Python package (`slyp/`) that does extraction, tax calculation and findings is a self-contained library with no network entry point at all; it is exercised only by `pytest` and the `tools/try_*.py` scripts.

The Next.js frontend does not call it. `app/upload/page.tsx` — the only live (non-commented) upload code path — calls `parsePayslipPdf()` in `lib/parse-pdf.ts`, which parses the PDF entirely in the browser with `pdfjs-dist` and a set of regex label-matchers, then stores the result in `localStorage`. It never issues a `fetch`, never opens a socket, never reads an API base URL. A repo-wide grep for `fetch(`, `axios`, `XMLHttpRequest`, `/api/`, and `localhost:` across every `.ts`/`.tsx`/`.js`/`.jsx` file returned **zero matches** outside `node_modules`.

The commit titled "connect frontend to backend" (`6081307`, merged into `main` as PR #6 this morning) does not do that. Diffing the file's history shows three successive rewrites of `app/upload/page.tsx`, each left in place as a commented-out block above the current code: the first used pure local mock data; the second called `lib/Api.ts`'s `parsePayslip()` under the comment *"Fires against your teammate's real endpoint script"* — but that function has never made a network call either, it just forwards to the same client-side `parsePayslipPdf()`; the third (current, live) code drops the pretence and calls the local parser directly. At no point in this file's history has it ever called an HTTP endpoint.

One consequence worth stating plainly for the architecture review at the top of the brief: because nothing in the running app ever calls an LLM (see R2 below), **rules 1 and 3 are not being violated on stage — they're not being exercised at all.** There is no AI in the demo path to explain anything, correct or not. The "Ask" feature (`components/prototype/AskSheet.tsx`) is a hardcoded keyword-matched FAQ (`lib/ask-answers.ts`) with a fake `setTimeout(600ms)` "thinking" delay — not a model call.

## Top 3 things most likely to break during a live five-minute demo

1. **Someone "helpfully" wires the frontend to the Python backend right before the demo, expecting it to work because the tests are described as passing.** It will crash on the first payslip with a normal (non-emergency) tax code, because `cumulative_income_tax_due()` — the default path — raises `NameError` unconditionally (F3), and the module won't even import without F2/F4 first. *Smallest fix: the three one-line import/typo fixes in F2–F4, done and re-tested well before the day, not live.*
2. **A judge asks "is this actually calling your Python tax engine?" and someone tries to demonstrate it.** It currently isn't (F1) — the answer live on stage would be no, and there's no quick way to make it yes without the fixes in (1) plus actually building an endpoint and a fetch call, which is not a five-minute task.
3. **Redaction is demoed with a payslip formatted slightly differently from the five sample payslips this was tuned against** (dashes/spaces work; punctuation like periods or slashes in a sort code/NI number doesn't — F6). This only matters if the Python pipeline gets connected per (1)/(2); until then it's a dormant risk, not a stage risk.

## Which of the three architectural rules held up

1. **"Code calculates, AI explains."** — **Not tested, because it's not exercised.** No LLM is called anywhere in the code path that actually runs on stage. The Python side that would call one (`slyp/extraction.py`) is unreachable from the frontend (F1) and, even on its own, three of its four downstream collaborators don't currently run (F2–F4). The "AI explains" half of the pitch has no live implementation right now — the "Ask" feature is a hardcoded FAQ lookup, not a model call.
2. **"A missing field is fine, a wrong field is not" (the confidence gate).** — **Partially proven, in isolation only.** Where I could reach it directly (patched import, bypassing F1/F4), the gate logic behaves correctly: an unreadable field genuinely suppresses the dependent finding rather than producing a hedged one. But this logic is not reachable from the live app at all, and I could not verify the UI-rendering half of the requirement (items 30-31) because there's no UI code path that consumes a gated `PayslipExtract` to check.
3. **"Nothing personal reaches the model."** — **Not violated on stage (because nothing reaches the model, period) — and independently, the safeguard has two confirmed bypasses if it's ever put in front of real traffic.** The redaction pipeline itself, tested directly and adversarially, has two reproducible PII leaks (F6): an NI number with periods and a sort code with slashes both sail through `redact()` **and** the "fail-closed" `assert_safe_to_send()` gate untouched, because the gate shares the exact regex that missed them in the first place. If this pipeline is connected before the demo without fixing F6, this rule would not actually hold under a live, non-cherry-picked test payslip.

## Verdict

**Not safe to run live in front of a room on 28 August in its current, disconnected state pretending to be connected — but safe, and honestly demoable, if the team stops claiming backend integration and demos exactly what's running today: a client-side PDF parser with a hardcoded FAQ.**

The frontend-only path (`parsePayslipPdf` → `localStorage` → dashboard) is the one piece of this repo I could fully exercise end-to-end through static tracing, and nothing in it is currently broken at the code level — it just isn't what the team is telling people it is. If the pitch on the day is "we read your payslip's text and calculate things client-side," that claim is true and low-risk. If the pitch on the day is "we call our Python tax engine and it talks to an AI to explain your payslip," that claim is false right now, and worse, the code behind it would crash immediately if switched on without fixing F2, F3, and F4 first (all three are one-line fixes, but none are done, and none are covered by a passing test — F5 shows the test suite doesn't even reach this code).

**Specific conditions for the demo to be safe:**
1. Before 28 Aug, the team explicitly decides and rehearses which of the two pipelines is being shown — do not attempt to switch this live or the night before.
2. If the Python pipeline is going to be shown at all (even just "here's the engine, here's proof it's correct" without a live connection), fix F2/F3/F4 first — they're one line each, but currently the module the pitch is built around does not import.
3. If the Python pipeline is connected to the frontend for the demo, fix F6 (or at minimum, hand-test the exact synthetic payslip that will be used on stage against the redaction pipeline beforehand — don't assume it generalizes from the five payslips it was tuned on).
4. Get someone with npm access to actually run the frontend once, upload a synthetic PDF through the real UI, and open the browser network tab before the day — this report's "not connected" conclusion is airtight from source, but nobody on this review has watched it happen with their own eyes yet, and that's worth five minutes before 28 Aug regardless of what the code says.
